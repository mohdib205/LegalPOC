# NyayaSetu MVP — Offline Indian Legal AI (Week 1 Skeleton)

A local, offline RAG pipeline for Indian legal Q&A with citation verification.
Domain in this skeleton: **Section 138 Negotiable Instruments Act (cheque bounce) cases** —
swap in your own domain/data by following the ingestion format below.

## Architecture

```
Query
  │
  ▼
Hybrid Search (ChromaDB semantic + Postgres/SQLite keyword)
  │
  ▼
LangChain prompt assembly (top-k chunks + query)
  │
  ▼
Ollama (Llama 3.1 8B / Mistral 7B) generates answer with citations
  │
  ▼
Citation Verifier (checks every cited case ID against the DB)
  │
  ▼
Streamlit UI (shows verified vs. unverified citations separately)
```

## Why this order matters

Retrieval and verification come before generation quality. An answer is only as
good as (a) whether the right judgment was retrieved and (b) whether the citation
it produced actually exists in your database. The verifier in `src/citation_verifier.py`
is the single most important file in this repo — it's what stops the system from
confidently citing a case that doesn't exist.

## Setup

```bash
pip install -r requirements.txt

# Pull a local model (requires Ollama installed: https://ollama.com)
ollama pull llama3.1:8b

# Initialize the database (SQLite by default — swap to Postgres by editing db.py)
python src/init_db.py

# Ingest sample data (replace with your real scraped judgments — see below)
python src/ingest.py --input data/sample_judgments/

# Build embeddings + vector index
python src/chunk_embed.py

# Run the app
streamlit run src/app.py
```

## Plugging in real data

`src/ingest.py` expects one JSON file per judgment in this shape:

```json
{
  "case_id": "NI138-2019-0042",
  "title": "Rajesh Kumar v. State Bank of India",
  "court": "Delhi High Court",
  "date": "2019-06-14",
  "judges": ["Justice A. Sharma"],
  "full_text": "..."
}
```

To pull real data from Indian Kanoon or India Code, write a scraper that respects
their API rate limits and terms of use, and have it write files in this format into
a folder, then point `ingest.py --input` at that folder. This sandbox can't reach
those domains, so that scraper needs to run on your own machine — I've left a
`src/scrape_template.py` stub with the request structure to fill in.

## What's NOT in this MVP (by design — see Week 2+)

OCR, citation graph, LoRA fine-tuning, drafting mode, multi-turn memory,
Hindi/Whisper support, Docker. Get this working end-to-end first.






## Folder structure

```
nyayasetu/
├── README.md
├── requirements.txt
├── data/
│   └── sample_judgments/       ← your hand-picked/fetched judgment JSON files land here
├── db/                          ← auto-created, don't touch by hand
│   ├── nyayasetu.db            ← SQLite database (generated by init_db.py)
│   └── chroma/                 ← vector index (generated by chunk_embed.py)
└── src/
    ├── db.py                   ← database schema + connection + search functions
    ├── init_db.py               ← run once to create the database
    ├── kanoon_client.py         ← talks to the Indian Kanoon API
    ├── fetch_judgments.py       ← search + fetch judgments, converts to ingest format
    ├── ingest.py                ← loads judgment JSON files into the database
    ├── chunk_embed.py           ← splits judgments into chunks, builds vector index
    ├── search.py                ← hybrid search (semantic + keyword)
    ├── citation_verifier.py     ← checks model citations against the database
    ├── rag_chain.py             ← ties retrieval + Ollama + verification together
    └── app.py                   ← Streamlit UI
```

## What goes in each file, and why it's ordered this way

| # | File | What it does | Depends on |
|---|---|---|---|
| 1 | `src/db.py` | Defines your database schema (`cases`, `citations`, `feedback` tables), a `get_connection()` helper, `case_exists()` (used by the verifier), and `search_keyword()` (keyword half of hybrid search). Build this first — everything else reads or writes through it. | Nothing |
| 2 | `src/init_db.py` | A 2-line script that just calls `init_db()` from `db.py`. Run once to create the actual `.db` file. | `db.py` |
| 3 | `src/kanoon_client.py` | Wraps Indian Kanoon's API: auth headers, a `search()` function, a `fetch_document()` function, and a paging helper. This is your only file that talks to the outside internet. | Your API token (env variable) |
| 4 | `src/fetch_judgments.py` | Uses `kanoon_client.py` to search, print candidates for you to review, then fetch full text for the IDs you pick — and writes each one as a JSON file in the exact shape `ingest.py` expects (`case_id`, `title`, `court`, `date`, `judges`, `full_text`). | `kanoon_client.py` |
| 5 | `data/sample_judgments/*.json` | The actual curated judgment files — either hand-written (for early testing) or produced by `fetch_judgments.py`. This is your 20–40 documents. | Nothing (just data) |
| 6 | `src/ingest.py` | Reads every JSON file in a folder and inserts it into the `cases` table (and keeps the full-text-search index in sync). | `db.py`, judgment JSON files |
| 7 | `src/chunk_embed.py` | Splits each judgment into chunks (tries splitting on FACTS/ISSUE/REASONING/HOLDING markers first, falls back to paragraph chunks), generates embeddings with a sentence-transformer, and stores them in ChromaDB. | `db.py`, ingested cases |
| 8 | `src/search.py` | Combines a semantic search against ChromaDB with a keyword search against SQLite, merges and dedupes the results — this is what "hybrid search" means concretely. | `chunk_embed.py`'s output, `db.py` |
| 9 | `src/citation_verifier.py` | Pulls every `[CASE: id]` marker out of a model's answer, checks each one against `db.case_exists()`, and returns a clean version of the answer with verified citations expanded to full case names and unverified ones flagged. **This is the file your whole pitch rests on.** | `db.py` |
| 10 | `src/rag_chain.py` | The glue: takes a question → calls `search.py` for context → builds a prompt instructing the model to cite using `[CASE: id]` → calls Ollama → passes the raw answer through `citation_verifier.py` → returns the final result. | `search.py`, `citation_verifier.py`, Ollama running locally |
| 11 | `src/app.py` | Streamlit UI: text box → calls `rag_chain.answer_question()` → displays the answer with verified citations in one color and unverified in another, plus a feedback thumbs up/down that logs to the `feedback` table. | `rag_chain.py`, `db.py` |
