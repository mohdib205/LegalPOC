# Project Context: NyayaSetu POC

## What is NyayaSetu?
NyayaSetu is an offline, AI-powered legal research tool designed for Indian law.

## POC Scope
The current Proof of Concept (POC) is strictly limited to cases under **Section 138 of the Negotiable Instruments Act, 1881** (cheque dishonour/bounce cases). 
The target dataset size is intentionally small: approximately 20–40 hand-curated real judgments. 
The system runs locally on a standard 16GB laptop without requiring a GPU.

## Core Differentiator
The core differentiator of NyayaSetu is **citation verification**. Unlike standard RAG pipelines that might hallucinate citations, NyayaSetu strictly checks every citation generated by the LLM against its local database before presenting it to the user. Reliability and accuracy are prioritized over eloquent answers.

## Technology Stack
- **Python**: Core programming language.
- **SQLite**: Structured metadata storage and keyword search (FTS5).
- **ChromaDB**: Vector store for embeddings.
- **Sentence-Transformers**: Embeddings generation (uses `all-MiniLM-L6-v2`).
- **Ollama**: Local LLM execution (Phi-3 Mini or Llama 3.1 8B).
- **Streamlit**: Web-based user interface.
- **Indian Kanoon API**: Fetching raw legal data.
- **python-dotenv**: Environment variable management.

## Important Architectural Decisions
- **Offline First**: All processing, search, and LLM generation happens locally to protect data privacy and avoid cloud API costs.
- **Hybrid Search**: Combines semantic meaning (ChromaDB) with exact keyword matching (SQLite FTS5) to maximize retrieval quality.
- **Verification over Generation**: The generated output is intercepted, and citations (formatted as `[CASE: case_id]`) are validated against SQLite before being rendered in the UI.

## Current Data Flow
1. Fetch judgments via Indian Kanoon API.
2. Store raw judgment JSON (`data/sample_judgments/`).
3. Ingest into SQLite (`cases` table).
4. Chunk judgments and generate embeddings.
5. Store vectors in ChromaDB.
6. User Query → Hybrid Search (SQLite + Chroma).
7. Retrieve top-k chunks.
8. Assemble Prompt + RAG via LangChain/Ollama.
9. Citation Verification (Check `[CASE: id]` against SQLite).
10. Streamlit UI displays verified/unverified answers.

## Out of Scope (Phase 2+)
The following features are **explicitly excluded** from the POC:
- Petition/document drafting
- Multi-turn conversational memory
- Citation graphing
- Fine-tuning (LoRA or full)
- Multilingual support (Hindi, etc.)
- Authentication/Authorization
- Dockerization
- Monitoring and Analytics
- Production infrastructure

## Project Directory Overview
- `data/`: Contains sample judgment JSON files.
- `db/`: Auto-generated database files (SQLite DB and ChromaDB vector store).
- `src/`: Core Python source code.
  - `app.py`: Streamlit UI.
  - `chunk_embed.py`: Splits text, generates embeddings.
  - `citation_verifier.py`: Core verification logic.
  - `db.py`: Database schema and SQLite connection.
  - `fetch_judgements.py`: Indian Kanoon fetcher script.
  - `ingest.py`: Loads JSONs into SQLite.
  - `init_db.py`: Initializes DB.
  - `kanoon_client.py`: Indian Kanoon API wrapper.
  - `rag_chain.py`: Connects search, Ollama, and verification.
  - `scrape_template.py`: Template for web scraping.
  - `search.py`: Hybrid search logic.

## Important Terminology
- **Chunk**: A section of a judgment text used for semantic search.
- **Citation Verifier**: The module that prevents hallucinations by checking case IDs against the local DB.
- **Hybrid Search**: A combination of vector-based semantic search and keyword-based search.
