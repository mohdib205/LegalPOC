# Changelog

All notable changes to the NyayaSetu MVP will be documented in this file.

## [Unreleased]
### Fixed
- **Generation Safety**: Transitioned `src/rag_chain.py` from raw `ollama.generate()` to `ollama.chat()` to enforce strict role separation between system constraints and user context, preventing prompt-leakage continuation. Also implemented a deterministic post-processing layer `truncate_continuation()` to safely strip any clear hallucinated conversational turns (`Question:`, `User:`, etc.) generated by the model.
- **Citation Robustness**: Modified `citation_verifier.py` to correctly extract and verify bare bracketed case IDs (e.g., `[NI138-2021-0089]`) alongside the canonical format (`[CASE: NI138-2021-0089]`) through a targeted regex restricted strictly to the NyayaSetu case-ID pattern.
- **Data Collection Workflow**: Enhanced `fetch_judgments.py` to support category-based file outputs, automatic duplicate skipping, bypassing already-downloaded judgments, and reading IDs directly from files (`--ids_file`). This significantly streamlines collecting the targeted 150 judgments across specific legal categories without manual ID copy-pasting.
### Fixed
- **Oversized Legal Chunks**: Bounded `chunk_by_legal_sections` in `src/chunk_embed.py` to sub-chunk sections exceeding 1200 characters. Previously, unbounded chunks caused silent truncation by the embedding model (`all-MiniLM-L6-v2`) and excessive LLM prompt size, leading to severe CPU latency.
- **Ollama Context Limit**: Explicitly added `num_ctx: 4096` and `num_predict: 500` to the Ollama API call in `src/rag_chain.py` to guarantee the model runs efficiently within a 16GB CPU-only hardware target and doesn't generate excessively long answers.
- **LLM Continuation**: Instructed the LLM to stop generating fake questions and added stop sequences to the generation configuration.
